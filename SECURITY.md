# Security Policy

## Supported Versions

Security fixes are provided for the latest released version.

| Version        | Supported |
| -------------- | --------- |
| Latest release | ✅ Yes    |
| Older releases | ❌ No     |

## Reporting a Vulnerability

Please do not report security vulnerabilities through public GitHub Issues.

To report a vulnerability, contact the maintainers privately:

**Email:** [security@v2hub.link](mailto:security@v2hub.link)

Please include:

- a description of the vulnerability;
- affected endpoint, component, or version;
- steps to reproduce;
- potential impact;
- any relevant logs, screenshots, or proof of concept.

We will acknowledge the report as soon as possible and investigate it confidentially.

## Disclosure

Please do not publicly disclose the vulnerability until a fix or mitigation is available.

Once the issue has been resolved, the maintainers may publish a security advisory describing the vulnerability and the released fix.

## Scope

Security reports related to the following are welcome:

- API authentication and authorization;
- API tokens and credentials;
- HMAC authentication;
- provider authentication flows;
- subscription access control;
- privilege escalation;
- sensitive data exposure;
- injection vulnerabilities;
- rate-limit bypasses;
- container and deployment security.

Reports that do not have a security impact, including ordinary bugs and feature requests, should be opened as GitHub Issues.
